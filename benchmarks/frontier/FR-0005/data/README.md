# Data dictionary

## Overall structure

The data contain two independent cohorts. Do not join `pair_id` and `participant_id` across cohorts.

- Mother–infant cohort: 94 `pair_id` values. All 94 pairs have matched maternal and cord-blood samples at delivery; 89 infants have a 6-month sample, and 88 have one later sample (19, 8, and 61 infants at 9, 10, and 11 months, respectively). There is no microbiological follow-up.
- Household longitudinal cohort: 442 baseline participants nested within 44 households. Follow-up visit records are available for 441 participants, and 431 have at least one IgG measurement. Participants may have repeated visits, repeated IgG measurements, and multiple culture-confirmed events.
- Time: in the household cohort, `study_day` is the number of days relative to each participant's enrollment, defined as day 0. Original dates were shifted uniformly, so actual calendar dates cannot be recovered, but within-person time intervals are preserved.
- Observation and censoring: some participants leave and re-enter follow-up, producing intermittent observation periods. Continuous intervals at risk are provided in `observation_periods.csv`. Time outside these intervals was not actively observed and cannot be treated as event-free time. Each interval is right-censored at `end_day` unless an event is recorded at that time.
- IgG: values are expressed in RLU/mL (relative Luminex units per milliliter) or their base-10 logarithm. `igg_measurements.csv` contains only actual measurements, with no prefilled values for unmeasured periods.
- Missingness: within existing rows, the text `NA` denotes missing data. An `NA` in a binary variable means the status cannot be determined and must not automatically be interpreted as 0. An entire visit that was not collected or is unavailable may be represented by absent rows rather than `NA` in each field; missing visits in the mother–infant cohort use this representation.

## Files

### `mother_infant_igg.csv`

Each row is one IgG measurement for a mother–infant pair, sample source, time point, and antigen. There are 1,825 rows and 94 `pair_id` values.

| Variable | Type / values | Meaning |
|---|---|---|
| `pair_id` | String | Anonymized mother–infant pair ID |
| `sample_source` | `mother`, `child` | Sample source; mothers were sampled only at delivery |
| `visit_label` | `DEL`, `6M`, `9M`, `10M`, `11M` | Visit label |
| `age_months` | Numeric; 0, 6, 9, 10, 11 | Months relative to delivery; maternal and cord samples are both coded as 0 |
| `antigen` | `GAC`, `SLO`, `SpyAD`, `SpyCEP`, `DNAseB` | Antigen |
| `igg_rlu_ml` | Continuous; 31.43–796,295.61 | IgG level, RLU/mL |
| `igg_log10_rlu_ml` | Continuous; 1.497–5.901 | `log10(igg_rlu_ml)` |
| `assay_within_standard_range` | Boolean | Whether at least one assay dilution for the measurement was within the standard-curve range |

The combination of `pair_id`, `sample_source`, `age_months`, and `antigen` defines a measurement. Under the study schedule, each later infant sample occurs at one of 9, 10, or 11 months; each infant does not have three later samples. Missing 6-month or later visits have no placeholder rows and must be identified from whether the `pair_id` appears at the corresponding visit.

### `participants.csv`

Each row is one participant in the household cohort, with 442 rows in total.

| Variable | Type / values | Meaning |
|---|---|---|
| `participant_id` | String | Anonymized participant ID |
| `household_id` | String; 44 households | Anonymized household ID; participants are nested within households |
| `age_years` | Integer; 0–70 | Anonymized pseudo-age in the public data, generated by substituting a random value within the original age group; do not treat it as the exact original age |
| `age_group` | `< 2 years`, `2-4 years`, `5-11 years`, `12-18 years`, `Over 18 years` | Original age group, preserved after anonymization |
| `sex` | `Male`, `Female` | Recorded biological sex |
| `baseline_household_size` | Continuous; 4–37 | Baseline household size; a few values are non-integers because of the original aggregation method |

### `followup_visits.csv`

Each row is a household-cohort follow-up record. There are 4,677 rows, with `study_day` ranging from 0–422 days. The original cohort combined approximately monthly routine throat/skin swab visits with additional consultations for new symptoms consistent with pharyngitis or pyoderma. Both observation mechanisms appear in this table, and the public source table has neither a reliable `visit_type` to distinguish them nor a separate `visit_id`. Records repeat within participants, and a participant may have multiple original records on the same day.

| Variable | Type / values | Meaning |
|---|---|---|
| `participant_id` | String | Anonymized participant ID; missing in 3 rows |
| `household_id` | String | Household ID; missing in the same 3 rows as `participant_id` |
| `study_day` | Continuous; 0–422 | Days relative to enrollment |
| `gas_event` | 0/1 | Whether the record contains any culture-confirmed *S. pyogenes* event |
| `gas_infection` | 0/1 | Whether there is a culture-confirmed infection event with manifestations of pharyngitis or pyoderma |
| `gas_carriage` | 0/1 | Whether there is culture-confirmed carriage without corresponding symptoms or signs; this may co-occur with infection at another site |
| `gas_pharyngitis` | 0/1 | Culture-confirmed pharyngitis |
| `gas_throat_carriage` | 0/1 | Culture-confirmed throat carriage |
| `gas_skin_carriage` | 0/1 | Culture-confirmed skin carriage |
| `pharyngitis` | 0/1 | Clinical manifestations of pharyngitis, without requiring a positive culture |
| `pyoderma` | 0/1 | Clinical manifestations of pyoderma, without requiring a positive culture |

`gas_event`, `gas_infection`, `gas_carriage`, `gas_pharyngitis`, `gas_throat_carriage`, and `gas_skin_carriage` are missing in 30, 18, 13, 1, 12, and 1 rows, respectively. The public protection-focused event table does not provide a separate field for culture-confirmed pyoderma; `pyoderma` records clinical manifestations only. Composite event variables need not equal simple row sums of site-specific variables, because statuses at different sites may co-occur.

### `observation_periods.csv`

Each row is one continuous observation/at-risk interval for a household-cohort participant. There are 702 rows for 441 participants. Each participant may have 1–5 non-overlapping intervals; this table explicitly represents interrupted follow-up and right censoring.

| Variable | Type / values | Meaning |
|---|---|---|
| `participant_id` | String | Anonymized participant ID |
| `interval_index` | Integer; 1–5 | Chronological index of the participant's observation interval |
| `start_day` | Continuous; 0–381.5 | Interval start relative to the participant's first enrollment |
| `end_day` | Continuous; 0–422 | Interval end/right-censoring time relative to first enrollment |

Gaps between adjacent intervals are not observed time, and intervals must not be joined by row number. Not all records in the other files fall within these intervals. Among records with identifiable IDs, 33 rows in `followup_visits.csv` (all coded as `gas_event=0`) fall outside the intervals, and another 3 rows cannot be matched because IDs are missing. In `igg_measurements.csv`, 60 rows corresponding to 12 participant–time points fall outside the intervals; coverage differences for household-size follow-up are described below. The mere presence of records outside the intervals does not establish continuous event-free time at risk. Handle these records according to the stated target population and observation rules.

### `igg_measurements.csv`

Each row is an IgG measurement for one household-cohort participant, actual sampling time, and antigen. There are 9,935 rows, corresponding to 1,987 unique participant–time points, 431 participants, and five antigens.

Of these, 60 rows (12 participant–time points) fall outside the individual's continuous observation intervals in `observation_periods.csv`. These are still measurements from actual blood samples, but they do not automatically make adjacent calendar time part of follow-up at risk.

| Variable | Type / values | Meaning |
|---|---|---|
| `participant_id` | String | Anonymized participant ID |
| `household_id` | String | Household ID |
| `study_day` | Continuous; 0–490 | Sampling time in days relative to enrollment; some samples were collected after the routine event follow-up window |
| `antigen` | `GAC`, `SLO`, `SpyAD`, `SpyCEP`, `DNAseB` | Antigen |
| `igg_log10_rlu_ml` | Continuous; 0.826–6.091 | IgG level, log10 RLU/mL; missing in 5 rows |

### `household_followup.csv`

Each row is a household-size follow-up record for one participant. There are 5,662 rows, with `study_day` ranging from 0–422 days. A participant may have multiple records on the same date. Even after including `visit_label`, the key `participant_id + study_day + visit_label` has 209 duplicate groups of two rows; these groups commonly contain one row with `household_size` and another with a missing value. This table has no separate row ID, so duplicates must be explicitly checked and handled before joining. Another 1,650 rows (1,520 participant–time points) fall outside individual `observation_periods.csv` intervals. The presence of household-level follow-up records does not imply that the member was within an individual period at risk.

| Variable | Type / values | Meaning |
|---|---|---|
| `participant_id` | String | Anonymized participant ID |
| `household_id` | String | Household ID |
| `visit_label` | String | Original visit label (e.g., `mv0`–`mv12` and additional-visit labels) |
| `study_day` | Continuous; 0–422 | Days relative to enrollment |
| `household_size` | Continuous; 3–41 | Household size for the record; missing in 209 rows |
| `rainy_season` | 0/1 | Whether the date falls within the local rainy season |

## Joining files

- Join household-cohort files using `participant_id`; use `household_id` for the household level.
- `study_day` uses the same individual enrollment-day origin across household-cohort files and can align records in time. Check one-to-many relationships before joining; do not merge by row number.
- `observation_periods.csv` gives the actual observation boundaries using that same time origin. Calendar gaps outside the intervals are not event-free follow-up.
- Pair mother–infant records only within their file using `pair_id`; these IDs cannot be joined to household-cohort IDs.
